# Phase 3 — Reproducible Fault Laboratory

## Goal

Phase 3 must create real, measurable vector-database failures without leaving
the demo database permanently damaged. Every experiment therefore has four
properties: deterministic parameters, an audit record, exact backup data, and
a verified restoration path.

## Implemented fault: incompatible embeddings

A model migration can leave old- and new-model vectors in one column even
though the two coordinate spaces are not comparable. The experiment simulates
that failure by selecting an exact percentage of documents and applying a
deterministic coordinate permutation and sign change. This preserves vector
dimension and norm but makes the selected vectors incompatible with query
vectors generated by the current model.

The transformation is a simulation of model incompatibility, not a claim that
a production model would use this exact mathematical operation.

## Safety design

- Only one fault run may be active at a time.
- Selection is reproducible through a fixed random seed.
- Original vectors and model-version labels are backed up transactionally.
- Injection either commits completely or rolls back completely.
- Restoration checks that exactly the expected number of rows was recovered.
- The full experiment wrapper attempts emergency restoration after a failure.
- `VACUUM ANALYZE` removes row churn created by injection and restoration.

## First measured experiment

Parameters: 25% of 480 rows, seed 42, 120 exact backup rows.

| Metric | Before | Fault active | Fully restored |
|---|---:|---:|---:|
| Recall@10 | 1.000 | 0.775 | 1.000 |
| Mean NN distance | 0.1675 | 0.2040 | 0.1675 |
| Distance shift | 0.0% | +21.8% | 0.0% |
| Model-version skew | 0.0% | 25.0% | 0.0% |
| Dead tuples | 0.0% | 100.0% | 0.0% after vacuum |
| Health status | Warning* | Critical | Warning* |

\*The warning is only `INDEX_NOT_USED`: PostgreSQL reasonably prefers a
sequential scan for the tiny 480-row table even though HNSW exists.

This proves that Phase 2 does not merely detect changed metadata: a realistic
embedding-space incompatibility causes both retrieval-quality loss and a
distance-distribution shift, and exact restoration returns both to baseline.

## Run the full experiment

From `demo` in PowerShell:

```powershell
.\db.ps1 up
.\demo.ps1 phase3-drift
```

For manual inspection between stages:

```powershell
# From selfheal_pgvector\scripts with the pgv environment active
python inject_fault.py model-drift --percentage 25 --seed 42
python eval_recall.py phase3_degraded
python inject_fault.py status
python inject_fault.py restore
python eval_recall.py phase3_recovered
```

## Remaining Phase 3 faults

1. Controlled Gaussian vector noise with exact backup and restoration.
2. HNSW index removal and recreation.
3. Intentional row churn to create measurable table bloat.
4. A results matrix mapping each injected fault to the signals it triggers.
